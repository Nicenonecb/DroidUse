# 人工接管首版

已接入 Phone 后端：运行页“查看后台并接管”打开安全窗口。请求暂停后等待任务步结束；后台截图仅显示在内存中，支持点击、滑动、返回、刷新、交回 AI、终止。手动接口绕过 OCR、模型和文件日志，不记录人工输入/画面。只记录接管请求与交回的时间事件。

服务使用同一把 Mutex 串行执行任务步和人工操作。批量阅读通过 HandoffRequestedException 退出当前批次到暂停态。模型调用尚未返回时会等待它结束，再展示可操作画面；迟到的模型动作被暂停检查丢弃。

需要人工处理的 NEEDS_USER 可保留会话与心跳；stop、总预算到期、资源保护及审计失败仍应清理。交回清空旧画面，TaskLoop.resume 后从新观察开始，不重发旧点击。

验证：
- 55项JVM测试通过，包含保留NEEDS_USER不清理、恢复重新观察、停止清理。
- Pixel 6 HandoffTest通过：手动观察/点击/再观察时文件集合及长度不变、模型不新增调用；交回后模型拿到新frameId。
- 实际Compose界面显示后台页面、刷新和交回按钮；人工刷新、交回后回到任务页，再通过停止结束。UI结构证据 `build/runtime-service-evidence/handoff-dialog.xml`，设备测试日志 `handoff-device-test.log`。
- 该UI测试是人为停止的任务，不算阅读完成成绩。

仍需完成：
- 独立中文输入/IME未就绪，当前仅手势接管，不能宣称任意登录输入已支持。
- 进程死亡后的完整任务恢复、跨应用/敏感系统确认仍待补。
- 批量阅读中途接管后再次自动阅读目前可能需要回第一章重建阅读进度；不能宣称无缝继续章节采集。
- 暂停/接管期间的低内存主动释放已补并验证（见下）；仍需更多故障和视频并行验证。

## 暂停健康检查补充

TaskLoop 在暂停/等待人工状态也调用只读 checkHealth。Phone 后端检查心跳失效与资源策略；严重压力会取消保留状态、关闭会话并禁止 resume，连接失效记录 EXECUTOR_DISCONNECTED。取消优先，避免用户主动停止被误记为连接故障。

57项JVM测试通过；真机HandoffTest两项通过，其中注入RUNNING_CRITICAL时处于暂停接管态，确认进入NEEDS_USER但不保留会话、不新增模型调用、不能恢复已关闭会话。另一个用例继续验证手动操作不落盘和交回后的新帧。证据 `build/runtime-service-evidence/handoff-health-test.log`。这是模拟系统内存通知，仍需真实视频并行压力测试。
